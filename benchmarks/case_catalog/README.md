# PWM Comprehensive Benchmark Case Catalog

> **168 modalities x 4 benchmarks (B1-B4) x all sub-cases = 297,920 total test instances**
>
> Each modality enumerates ALL architecture variants, image sizes, compression ratios,
> noise levels, and mismatch combinations. Cases use the 11 typed primitives
> (Src, P, M, R, Pi, F, C, W, Sigma, S, D) to describe real physical elements.

## Benchmark Structure (B1-B4)

| Benchmark | Input | Output | What It Tests |
|-----------|-------|--------|---------------|
| **B1**: Design | prompt + original-spec (optional) | spec | Router (LLM) ability to generate valid imaging system specs |
| **B2**: Forward + Reconstruct | spec | reconstruction + feedback | Contestant ability to build forward model and reconstruct |
| **B3**: System Identification | dataset + prompt + original-spec (optional) | spec | Contestant ability to identify system parameters from data |
| **B4**: Correct + Diagnose | dataset + spec | correction + reconstruction + feedback | Full pipeline: mismatch correction + reconstruction |

### B1 Detail: Multi-round spec generation
- Spec has multiple versions (easy/medium/hard prompts) to test router quality
- Contestants can chat multiple rounds to refine spec
- Spec describes: source, system elements (lens, mask, prism...), using 11 primitives
- **Scoring**: compare generated spec against ground-truth spec

### B2 Detail: Forward + Reconstruct
- Spec fully specifies imaging system -> can directly build forward model
- Must handle: all noise levels, all mismatch types
- Variants: SD-CASSI vs DD-CASSI etc., image sizes, compression ratios
- **Scoring**: PSNR, SSIM, SAM vs ground truth

### B3 Detail: System Identification
- Dataset includes measurement + matrix (+ optional metadata)
- Each dataset has a **true-spec** with ALL parameters (mask rotation, shift, noise level)
- Contestant only knows parameter RANGES, not exact values
- Generated spec compared to true-spec
- **Scoring**: parameter estimation error, spec quality metric

### B4 Detail: Correct + Diagnose
- Dataset + (possibly erroneous) spec -> correction + reconstruction + feedback
- Another **true-spec** serves as ground truth for judging correction quality
- True-spec also contains how to improve the spec and real experimental system
- **Scoring**: rho (mismatch correction quality), PSNR, feedback quality

## Case Count Dimensions

For each modality, cases are generated from these dimensions:

| Dimension | Typical Values | Count |
|-----------|---------------|-------|
| System variants | Modality-specific (e.g., SD/DD/R-CASSI) | 2-9 |
| Image sizes | Small (64/128), Medium (256), Large (512/1024) | 3-4 |
| Compression ratios | Modality-specific | 2-4 |
| Noise levels | Clean, Low, Medium, High | 4 |
| Mismatch levels (B2-B4) | M0 (none), M1 (single), M2 (compound), M3 (real), M4 (adversarial) | 5 |
| Prompt difficulty (B1) | Easy, Medium, Hard, Adversarial | 4 |

**Total per modality per benchmark** = variants x sizes x ratios x noise x mismatch
