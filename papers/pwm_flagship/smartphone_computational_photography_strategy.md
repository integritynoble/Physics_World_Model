## 1. What Is Smartphone Computational Photography?

Smartphone computational photography uses **software algorithms, machine learning, and multi-frame capture** to overcome the fundamental physical limitations of tiny sensors and lenses. Unlike traditional photography that relies on optical hardware, computational photography treats image formation as a **computational inverse problem**: given noisy, limited measurements from a small sensor, reconstruct the best possible image.

Every major smartphone camera feature — HDR, Night Mode, Portrait, Zoom, Stabilization — is an **inverse problem** with a **forward model** describing the physics of image formation. This is exactly what PWM formalizes.

### The Core Insight

> **Every smartphone camera feature is an instance of the same 11 primitives and 3 gates that govern MRI, CT, and coded aperture cameras.**

The forward model of an iPhone's Night Mode and an MRI scanner share the same mathematical structure: a scene is transformed through a chain of physical operations (modulation, convolution, sampling, detection), and the reconstruction fails for exactly three reasons (information deficiency, noise, or operator mismatch).

### Why This Matters

- **4 billion** smartphone users worldwide

- Camera is the **#1 feature driver** for premium smartphone purchases

## 2. Eight Core Features Mapped to PWM's 11 Primitives

### 2.1 HDR / Multi-Exposure Fusion

**What it does:** Captures a burst of 3–15 frames at different exposures, aligns and merges them to simultaneously reduce noise and expand dynamic range. Google's HDR+ (2014) pioneered the constant-underexposure burst approach; Apple's Deep Fusion (2019) added per-pixel neural optimization.

**The physics:** Each frame `y_k` is generated by the scene radiance `x` passing through exposure gain, lens PSF, sensor saturation, and detection:

**OperatorGraph DAG (per frame k):**
```
Source(x) → M(t_k) → C(h_lens) → Λ(saturation) → D(g, η_sq) → y_k
```

| Node | Primitive | Physical action |
|------|-----------|----------------|
| `M(t_k)` | Modulate | Exposure time as scalar gain on radiance |
| `C(h_lens)` | Convolve | Lens PSF (diffraction + aberrations) |
| `Λ(sat)` | Transform | Pixel full-well saturation clipping (saturation family) |
| `D(g, η)` | Detect | CMOS sensor intensity-square-law + analog gain |

**Full multi-frame DAG:** K parallel branches `M → C → Λ → D`, one per exposure.

**Gate 3 Mismatch Parameters:**

| Parameter | Primitive | Description | Typical Error |
|-----------|-----------|-------------|---------------|
| Exposure timing `t_k` | M | Shutter jitter | ~0.1–0.5% |
| Lens PSF drift | C | Aberration vs. focus position | 0.1–0.3 px |
| Saturation knee | Λ | Full-well capacity spatial variation | 2–5% |
| **Scene motion between frames** | **Unmodeled** | **Objects move during burst** | **0.5–3 px** |

**Dominant failure:** Scene motion ghosting — the forward model assumes a static scene, but moving objects create structured artifacts. This is a **Gate 3 mismatch**: the forward model's static-scene assumption doesn't match reality.

**ISP maturity:** High for static scenes. Ghosting in dynamic scenes remains the primary failure.

### 2.2 Night Mode

**What it does:** Captures 6–15 frames with longer per-frame exposures (50–500ms, up to 6 seconds total), using "motion metering" to adaptively choose exposure based on hand shake. Aligns frames, rejects ghosted regions, merges, and applies learned tone mapping for natural-looking low-light images.

**OperatorGraph DAG (per frame k):**
```
Source(x) → C(h_motion,k) → M(t_k) → C(h_lens) → D(g, η_sq) → y_k
```

| Node | Primitive | Physical action |
|------|-----------|----------------|
| `C(h_motion,k)` | Convolve | Motion blur kernel (hand shake trajectory during sub-exposure) |
| `M(t_k)` | Modulate | Exposure gain (longer than HDR) |
| `C(h_lens)` | Convolve | Optical PSF |
| `D(g, η)` | Detect | CMOS at very low photon counts (shot-noise dominated) |

**Canonical chain:** `C → M → C → D` (4 nodes, depth 4)

**Gate 3 Mismatch Parameters:**

| Parameter | Primitive | Description | Typical Error |
|-----------|-----------|-------------|---------------|
| **Motion kernel `h_motion,k`** | **C** | **Hand-shake trajectory per frame** | **1–5 px blur** |
| Inter-frame alignment | — | Registration error between burst frames | 0.1–0.5 px |
| Exposure metering | M | AE error in darkness | 5–15% |
| Focus accuracy | C | PDAF unreliable in low light | 0.2–1.0 px |
| Flat-field / vignetting | M | Lens shading correction error | 2–5% radial |
| Read noise model | D | Noise varies with temperature/gain | 5–10% |

**Dominant failure:** Motion blur kernel estimation — the ISP assumes an affine homography but the true hand trajectory is 6-DOF, creating spatially-varying blur that is only partially corrected. **Gate 2 (noise) co-dominates** here because photon starvation is genuine.

**ISP maturity:** Medium-high on flagships. Motion blur on moving objects and over-sharpening artifacts remain visible.

### 2.3 Portrait Mode (Computational Bokeh)

**What it does:** Simulates shallow depth-of-field by: (1) estimating a per-pixel depth map (stereo, ToF, or monocular neural network); (2) segmenting subject from background; (3) applying a depth-dependent blur kernel simulating a large-aperture lens.

**The physics being simulated (target forward model):**
```
Source(x(r,z)) → C(h_bokeh(z)) → Σ_z → D(g, η) → y
```

| Node | Primitive | Physical action |
|------|-----------|----------------|
| `C(h_bokeh(z))` | Convolve | Depth-dependent bokeh PSF (disk/polygon, radius ∝ \|1/z − 1/z_focus\|) |
| `Σ_z` | Accumulate | Summation over depth planes |
| `D(g, η)` | Detect | Standard CMOS detection |

**Depth estimation branch (parallel):**
```
Source(x) → [C(h_L) → D] ‖ [C(h_R) → D]  (stereo pair or dual-pixel)
```

Disparity between the two `C → D` chains encodes depth.

**Canonical chain (synthesis):** `C(h(z)) → Σ → D` (3 nodes, depth 3)

**Gate 3 Mismatch Parameters:**

| Parameter | Primitive | Description | Typical Error |
|-----------|-----------|-------------|---------------|
| **Depth map `z(r)`** | **C(h(z))** | **Depth estimation error at edges** | **5–20% relative depth** |
| Bokeh kernel shape | C | Ideal disk vs. actual aperture shape | Qualitative |
| Edge segmentation | — | Hair/fur boundary misclassification | 1–3 px |
| Specular highlights | Λ | Point-source bokeh should be disk, not Gaussian | — |
| Alpha matting | Σ | Depth boundary compositing error | — |

**Dominant failure:** Depth map error at object boundaries — incorrect `z(r)` causes the depth-dependent convolution kernel to switch at wrong pixel locations. Hair, glasses, transparent objects, and thin structures produce the most visible artifacts.

**ISP maturity:** Medium. Convincing at arm's length but fails at fine boundaries. The gap between iPhone/Pixel and a real f/1.4 lens is still clearly visible.

### 2.4 Computational Zoom (Super-Resolution)

**What it does:** Uses multi-frame fusion to achieve resolution beyond the Nyquist limit. Sub-pixel offsets from natural hand tremor across burst frames provide diversity for super-resolution reconstruction. Google's approach adapts astronomical "drizzle" via kernel regression on raw Bayer data.

**OperatorGraph DAG (per frame k):**
```
Source(x_HR) → S(Ω_k) → C(h_lens) → D(g, η) → y_k
```

| Node | Primitive | Physical action |
|------|-----------|----------------|
| `S(Ω_k)` | Sample | Sub-pixel spatial sampling on shifted grid (hand tremor offset) |
| `C(h_lens)` | Convolve | Lens PSF + anti-aliasing filter |
| `D(g, η)` | Detect | CMOS sensor |

**Canonical chain:** `S → C → D` (3 nodes, depth 3)

**Gate 3 Mismatch Parameters:**

| Parameter | Primitive | Description | Typical Error |
|-----------|-----------|-------------|---------------|
| **Sub-pixel shift `δ_k`** | **S** | **Frame-to-frame registration error** | **0.05–0.2 px** |
| Lens PSF variation | C | Spatially varying aberration | 0.1–0.5 px |
| Anti-aliasing filter | C | OLPF model vs. reality (many phones lack OLPF) | — |
| Motion blur | C | Residual motion during sub-exposure | 0.1–0.3 px |
| Geometric distortion | Λ | Barrel/pincushion causes position-dependent shift | 0.1–1% |

**Dominant failure:** Sub-pixel registration accuracy — errors in `δ_k` estimation directly produce aliasing artifacts. At >5× zoom, the problem transitions from Gate 3 to **Gate 1** (insufficient information), and ISPs resort to learned hallucination — generating plausible but fabricated detail (Samsung's controversial 100× Space Zoom).

**ISP maturity:** Medium-high for 2–3×. At >5×, ISPs "hallucinate" detail that was never captured — a fundamental Gate 1 limitation.

### 2.5 Video Stabilization (EIS + OIS)

**What it does:** Combines Optical Image Stabilization (hardware lens/sensor shift via MEMS gyroscopes) with Electronic Image Stabilization (software crop and re-projection using gyroscope data and optical flow).

**OperatorGraph DAG (per frame k):**
```
Source(x) → M(H_warp,k) → C(h_lens(OIS_state)) → S(Ω_crop) → D(g, η) → y_k
```

| Node | Primitive | Physical action |
|------|-----------|----------------|
| `M(H_warp,k)` | Modulate | Geometric warp (rotation + translation from hand shake) |
| `C(h_lens(OIS))` | Convolve | Time-varying PSF (OIS shifts lens elements) |
| `S(Ω_crop)` | Sample | EIS crops ~10–20% of sensor for stabilization margin |
| `D(g, η)` | Detect | CMOS sensor |

**Canonical chain:** `M → C → S → D` (4 nodes, depth 4)

**Gate 3 Mismatch Parameters:**

| Parameter | Primitive | Description | Typical Error |
|-----------|-----------|-------------|---------------|
| Gyroscope-to-pixel calibration | M | IMU rotation → pixel displacement mapping | 0.1–0.5 px/frame |
| **Rolling shutter timing** | **—** | **Rows read at different times; model assumes global shutter** | **1–5 ms/frame** |
| OIS lens position | C | Actual vs. commanded lens shift | 0.05–0.2 px |
| Homography model order | M | Affine vs. projective vs. mesh warp | Structural |
| **Parallax (near objects)** | **M** | **2D warp cannot correct 3D parallax** | **Depth-dependent** |

**Dominant failure:** Rolling-shutter distortion (forward model assumes global shutter but CMOS reads row-by-row) and parallax from nearby objects (2D homography cannot handle 3D scene geometry).

**ISP maturity:** High for rotation/translation. Near-gimbal smoothness on flagship devices. Parallax and rolling shutter remain edge-case failures.

### 2.6 Multi-Camera Fusion (Wide + Ultrawide + Telephoto)

**What it does:** Modern smartphones have 2–5 cameras with different focal lengths, sensors, and lens designs. The ISP fuses data across cameras for seamless zoom transitions, depth estimation, and extended dynamic range.

**OperatorGraph DAG (per camera c):**
```
Source(x) → M(H_c) → C(h_lens,c) → M(v_c) → D(g_c, η_c) → y_c
```

| Node | Primitive | Physical action |
|------|-----------|----------------|
| `M(H_c)` | Modulate | Geometric warp (homography mapping wide→camera_c coordinates) |
| `C(h_lens,c)` | Convolve | Per-camera PSF (different lens design, focal length) |
| `M(v_c)` | Modulate | Vignetting and flat-field unique to each module |
| `D(g_c, η_c)` | Detect | Per-sensor gain, noise floor, color filter array |

**Full DAG (3-camera system):**
```
Source(x)
  ├── M(H_wide)  → C(h_wide)  → M(v_wide)  → D(g_wide)  → y_wide
  ├── M(H_ultra) → C(h_ultra) → M(v_ultra) → D(g_ultra) → y_ultra
  └── M(H_tele)  → C(h_tele)  → M(v_tele)  → D(g_tele)  → y_tele
```

**Canonical chain (per camera):** `M → C → M → D` (4 nodes, depth 4)

**Gate 3 Mismatch Parameters:**

| Parameter | Primitive | Description | Typical Error |
|-----------|-----------|-------------|---------------|
| **Extrinsic calibration (R, t)** | **M(H)** | **Inter-camera rotation/translation** | **0.1–1.0 px parallax** |
| **Color/white-balance matching** | **D(g)** | **Different sensors have different spectral response** | **2–5% color shift** |
| PSF cross-calibration | C(h) | Different lens MTF at different focal lengths | Structural |
| Vignetting correction | M(v) | Per-camera flat-field error | 1–3% radial |
| Geometric distortion | Λ | Different barrel/pincushion per lens | 0.1–0.5% |
| Temporal sync | — | Inter-camera shutter sync error | 0.5–2 ms |

**Dominant failure:** Inter-camera parallax during zoom transitions — the 10–15mm baseline between cameras causes depth-dependent misalignment that a single homography cannot handle. Color mismatch between sensors (different spectral response curves) causes visible color jumps when switching cameras.

**ISP maturity:** Medium. Flagship devices handle it well in well-lit conditions. Close subjects and mixed lighting expose the fusion seams.

### 2.7 RAW Processing / Color Science (ISP Pipeline)

**What it does:** The full ISP pipeline converts a raw Bayer mosaic into a display-ready sRGB image. This is the most fundamental camera processing chain, involving: black level correction, demosaicing, noise reduction, white balance, color correction matrix (CCM), tone mapping, sharpening, and compression.

**OperatorGraph DAG:**
```
Source(x_scene(λ)) → M(CFA(λ)) → Σ_λ → C(h_lens(λ)) → S(Bayer) → D(g) → RAW
```

| Node | Primitive | Physical action |
|------|-----------|----------------|
| `M(CFA(λ))` | Modulate | Color filter array spectral sensitivity per pixel (R, G, or B) |
| `Σ_λ` | Accumulate | Integration over wavelength band |
| `C(h_lens(λ))` | Convolve | Wavelength-dependent PSF (chromatic aberration) |
| `S(Bayer)` | Sample | CFA samples one color per pixel (2× spatial undersampling per channel) |
| `D(g)` | Detect | CMOS photodiode response with analog gain and ADC |

**Canonical chain:** `M → Σ → C → S → D` (5 nodes, depth 5)

**Gate 3 Mismatch Parameters:**

| Parameter | Primitive | Description | Typical Error |
|-----------|-----------|-------------|---------------|
| CFA spectral response | M | Nominal vs. actual filter transmission | 2–5% per channel |
| **Color matrix (3×3)** | **M** | **Scene illuminant assumption (D65 vs. actual)** | **5–15% under mixed lighting** |
| Chromatic aberration | C | Lateral/longitudinal CA model error | 0.1–0.5 px/channel |
| Black level / pedestal | D | Per-row/column fixed-pattern noise | 0.1–0.5 DN |
| Lens shading | M | Vignetting + color shading correction | 1–5% radial |
| Defective pixel map | S | Dead/hot pixel locations drift with temperature | — |
| Analog gain linearity | D | Non-linear response at extreme signal levels | 0.5–2% |

**Dominant failure:** Illuminant estimation (white balance) — the color matrix assumes a specific spectral power distribution, but under mixed lighting (tungsten + fluorescent + daylight), no single 3×3 matrix is correct everywhere. This is a **spatially-varying operator mismatch** in the Modulate node.

**ISP maturity:** Very high. The most mature pipeline (15+ years of refinement). Mixed-lighting white balance remains the primary failure.

### 2.8 Panorama Stitching

**What it does:** The camera rotates through K poses, capturing overlapping views. Frames are registered, warped onto a common projection (cylindrical/spherical), exposure-equalized, and blended.

**OperatorGraph DAG (per frame k):**
```
Source(x) → M(H_rot,k) → C(h_lens) → M(v) → D(g, η) → y_k
```

| Node | Primitive | Physical action |
|------|-----------|----------------|
| `M(H_rot,k)` | Modulate | Rotation matrix maps world → frame k image plane |
| `C(h_lens)` | Convolve | Lens PSF (consistent across frames) |
| `M(v)` | Modulate | Vignetting (must be corrected before blending) |
| `D(g, η)` | Detect | Same sensor for all frames |

**Canonical chain (per frame):** `M → C → M → D` (4 nodes, depth 4)

**Gate 3 Mismatch Parameters:**

| Parameter | Primitive | Description | Typical Error |
|-----------|-----------|-------------|---------------|
| Rotation estimate `R_k` | M(H) | IMU + feature matching error | 0.01–0.1 deg |
| **Translation (non-zero baseline)** | **M(H)** | **Hand not rotating around optical center** | **1–5 mm** |
| Lens distortion | Λ | Barrel distortion correction residual | 0.1–0.5% at edges |
| Vignetting correction | M(v) | Flat-field error causes brightness seams | 1–3% |
| Exposure variation | M(t) | Auto-exposure changes between frames | 5–20% brightness |
| Rolling shutter | — | Row-dependent timestamp during rotation | 1–3 px row shift |

**Dominant failure:** Parallax from non-zero translation — the user's hand translates while rotating, but the homography model assumes pure rotation. This produces visible stitching seams near foreground objects.

**ISP maturity:** High for static outdoor scenes. Foreground parallax and exposure banding remain edge-case failures.

## 3. Cross-Cutting Insights: Why PWM Matters Here

### Insight 1: Smartphone cameras use only 6 of 11 primitives

All 8 features draw from **{M, C, S, D, Σ, Λ}** — never P (Propagate), Π (Project), F (Encode), W (Disperse), or R (Scatter). This makes physical sense: smartphones are **incoherent intensity-detection systems in the geometric optics regime**. Wave propagation, Radon projection, Fourier encoding, spectral dispersion, and scattering are not part of the smartphone imaging chain.

| Primitive | Used in smartphone? | Why / why not |
|-----------|-------------------|---------------|
| P (Propagate) | No | Geometric optics regime — no wave effects |
| **M (Modulate)** | **Yes — all 8 features** | Exposure gain, geometric warps, filters, masks |
| Π (Project) | No | No line-integral geometry |
| F (Encode) | No | No Fourier-domain sensing |
| **C (Convolve)** | **Yes — all 8 features** | Lens PSF, motion blur, bokeh kernels |
| **Σ (Accumulate)** | **Yes — 3 features** | Spectral integration, depth-plane fusion |
| **D (Detect)** | **Yes — all 8 features** | CMOS sensor in every chain |
| **S (Sample)** | **Yes — 4 features** | Bayer pattern, EIS crop, sub-pixel shift |
| W (Disperse) | No | No wavelength-dependent spatial shift |
| R (Scatter) | No | No scattering physics |
| **Λ (Transform)** | **Yes — 3 features** | Saturation, distortion, tone curves |

**Implication for the paper:** This 6-of-11 pattern is itself a validation of the Finite Primitive Basis Theorem. The smartphone camera, despite its immense engineering complexity, draws from a strict subset of the same 11 primitives that describe MRI and CT.

### Insight 2: Gate 3 dominates in 6 of 8 features

Under standard operating conditions (adequate lighting), **Gate 3 (operator mismatch) is the dominant failure mode** in 6 of 8 smartphone features:

| Feature | Dominant Gate | Why |
|---------|--------------|-----|
| HDR | Gate 3 | Scene motion mismatch |
| Night Mode | Gate 3 + **Gate 2** | Motion blur kernel + photon starvation |
| Portrait Mode | Gate 3 | Depth map error |
| Computational Zoom (≤3×) | Gate 3 | Registration error |
| Computational Zoom (>5×) | **Gate 1** | Insufficient information → hallucination |
| Video Stabilization | Gate 3 | Rolling shutter + parallax |
| Multi-Camera Fusion | Gate 3 | Inter-camera calibration |
| RAW / Color Science | Gate 3 | White balance mismatch |
| Panorama | Gate 3 | Translation parallax |

**The only exceptions:**
- **Night Mode** at very low light: Gate 2 (noise) co-dominates because photon starvation is genuine
- **Extreme zoom (>5×):** Gate 1 (information deficiency) dominates — the number of independent measurements is genuinely insufficient, and ISPs resort to hallucination

**This is exactly the Triad prediction:** Gate 3 dominates when operating above the Gate 1 floor (sufficient measurements) and Gate 2 floor (sufficient SNR).

### Insight 3: The dominant Gate 3 parameter is geometric in 6 of 8 cases

| Feature | Dominant Gate 3 Parameter | Type |
|---------|--------------------------|------|
| HDR | Scene motion between frames | Geometric |
| Night Mode | Hand-shake trajectory | Geometric |
| Portrait | Depth map at boundaries | Geometric |
| Zoom | Sub-pixel registration | Geometric |
| Stabilization | Rolling shutter + parallax | Geometric |
| Multi-camera | Inter-camera extrinsics | Geometric |
| RAW/Color | Illuminant estimation | Spectral |
| Panorama | Translation parallax | Geometric |

**Implication:** For smartphones, **calibration investment should focus on spatial registration and depth estimation** — which is exactly what the industry has done (hardware-accelerated feature matching, LiDAR/ToF, neural depth estimators). PWM's framework formally explains this empirical industry pattern.

### Insight 4: The multi-frame tension

Features 1, 2, 4, 5, 6, and 8 are all multi-frame problems where the forward model assumes K observations of the **same scene** from different viewpoints/exposures. But the scene changes between frames (objects move, lighting changes). This temporal scene change is an **unmodeled Gate 3 mismatch** that no forward-model refinement within the static-scene assumption can fix.

The ISP solution is to **detect and mask out regions of change** (ghosting detection) — which is an implicit acknowledgment that the static-scene forward model is mismatched. PWM could formalize this as a **time-varying Modulate node** and provide principled ghost detection via cross-residual analysis (the same technique validated on CASSI and CACTI real data in the paper).

## Appendix: Summary of All 8 Features

| # | Feature | DAG | Nodes/Depth | Primitives Used | Dominant Gate 3 | ISP Maturity |
|---|---------|-----|-------------|-----------------|-----------------|-------------|
| 1 | HDR Fusion | `[M→C→Λ→D] × K` | 4/4 | M, C, Λ, D | Scene motion | High |
| 2 | Night Mode | `C→M→C→D` | 4/4 | M, C, D | Motion blur kernel | Med-High |
| 3 | Portrait Mode | `C(h(z))→Σ→D` | 3/3 | C, Σ, D | Depth map edges | Medium |
| 4 | Comp. Zoom | `S→C→D` | 3/3 | S, C, D | Sub-pixel registration | Med-High |
| 5 | Video Stab. | `M→C→S→D` | 4/4 | M, C, S, D | Rolling shutter | High |
| 6 | Multi-Camera | `[M→C→M→D] × cams` | 4/4 | M, C, D | Inter-camera parallax | Medium |
| 7 | RAW/Color | `M→Σ→C→S→D` | 5/5 | M, Σ, C, S, D | White balance | Very High |
| 8 | Panorama | `[M→C→M→D] × K` | 4/4 | M, C, D | Translation parallax | High |

**Union of primitives across all 8 features:** {M, C, S, D, Σ, Λ} = **6 of 11**

**Primitives NOT used:** {P, Π, F, W, R} — these are wave/coherent/projection/dispersion/scattering physics, absent from geometric-optics incoherent smartphone imaging.
