% ABSTRACT
% =====================================================================
\noindent\textbf{Abstract.}
AI-generated code can now produce numerical solvers from natural-language problem descriptions, yet it does so without error certificates---leaving scientists unable to distinguish correct from incorrect output. Here we show that a formally grounded validation step, inserted between problem specification and numerical execution, is both necessary and sufficient to close this gap. We define a \emph{simulability class} $\mathfrak{S}$ of problems admitting bounded-error numerical solutions (Definition~\ref{def:simulability}) and prove that, for problems in $\mathfrak{S}$ whose discretization decomposes over a 12-operation primitive basis, a three-agent pipeline (Plan, Validate, Compute) produces solutions satisfying $\norm{\hat{x} - x^*} \leq \varepsilon$ for any prescribed tolerance $\varepsilon > 0$ (Theorem~\ref{thm:main}). The theorem rests on classical convergence theory (Lax--Richtmyer); the contribution is an automated pipeline that \emph{identifies and constructs} the convergent discretization from natural language, with each agent addressing a distinct failure mode. We validate deeply in three domains with real measured data: clinical CT reconstruction (200 cases, 99\% of expert quality), seismic full-waveform inversion on the Marmousi-2 benchmark (95\% of expert quality), and GRI-Mech~3.0 combustion ignition delay against shock-tube measurements (6.3\% error). A controlled comparison against GPT-4---given both raw descriptions and structured specifications---shows that AI code generation without formal validation silently fails on 58\% of frontier problems; our Validation Agent reduces this to below 6\%. A prospective benchmark of 72 tasks contributed by 12 external scientists, none involved in development, confirms that the pipeline generalizes to unseen domains and problem types. Code, specifications, benchmark tasks, and execution logs are publicly available.

\section{Introduction}
% =====================================================================

\textbf{The problem.}
Large language models can now generate numerical simulation code from natural-language descriptions of scientific problems~\cite{karniadakis2021,lu2021}. A researcher describes a differential equation, and the model produces a working solver---often in seconds. This capability could democratize computational science by removing the programming barrier that prevents most domain scientists from running simulations---much as AlphaFold~\cite{jumper2021} democratized protein structure prediction. But there is a critical gap: the generated code comes with no guarantee that its output is correct. In a scientific culture already facing a reproducibility crisis~\cite{baker2016}, silent computational errors compound the problem. When the code produces a wrong answer---a laminar solution for a turbulent flow~\cite{pope2000}, a missing electron-correlation term in a quantum calculation, a numerically unstable time integrator for a stiff chemical system---the scientist has no way to detect the error.

\textbf{The claim.}
We show that formal mathematical validation, implemented as an autonomous agent that executes well-posedness proofs and error-budget computations, is necessary and sufficient to close this gap for the class of problems $\mathfrak{S}$ defined below. ``Necessary'' is demonstrated by ablation: removing the Validation Agent causes the pipeline to produce silently wrong results on 42\% of tested problems (Table~\ref{tab:llm_comparison}, ``No $\Agent_V$'' column). ``Sufficient'' is demonstrated by a controlled comparison: inserting the Validation Agent reduces the silent-failure rate of AI-generated solvers from 58\% (GPT-4 alone) to below 6\% (Table~\ref{tab:llm_comparison}), while providing formal error certificates that raw code generation never produces.

\textbf{What this paper does not claim.}
We do not claim universality. The theorem holds for problems whose discretization decomposes over a specific 12-operation basis; we have verified this for 25 numerical method families (Supplementary Table~S1) but do not claim it covers all possible methods. The pipeline does not outperform domain-optimized solvers; it trades 1--12\% peak accuracy for full automation. The formal error bound is in the $L^2$ norm and does not guarantee qualitative physical correctness in all cases; we report a 6\% residual rate of qualitative failures (Section~\ref{sec:failure}) and introduce a domain-quality gate to reduce it.

\subsection{Scope: The Simulability Class}
\label{sec:scope}
% -------------------------------------------------------------------

\begin{definition}[Simulability Class $\mathfrak{S}$]
\label{def:simulability}
A scientific problem $P$ belongs to $\mathfrak{S}$ if it satisfies:
\begin{enumerate}[nosep]
\item \textbf{Finitely specifiable}: representable as $(\Domain, \mathcal{E}, \mathcal{B}, \mathcal{I}, \mathcal{O}, \varepsilon)$.
\item \textbf{Convergently discretizable}: admits a mesh/basis discretization with order-$q$ convergence.
\item \textbf{Primitive-decomposable}: the discretized computation decomposes into a finite DAG over the 12 primitives in Table~\ref{tab:primitives} (Methods).
\item \textbf{Observable}: $\mathcal{O}$ consists of well-defined solution functionals.
\item \textbf{Metrizable}: a computable norm quantifies $\norm{\hat{x} - x^*}$.
\end{enumerate}
\end{definition}

This class contains all Hadamard-well-posed PDEs~\cite{hadamard1902}, Lipschitz ODEs, regularized inverse problems, and their compositions. It excludes undecidable problems~\cite{turing1936,rice1953}, those requiring infinite-precision arithmetic (cf.~\cite{blum1989}), and individual quantum measurement outcomes (Supplementary Section~S2). We emphasize that condition~3 is an \emph{empirical} scope limitation verified for 25 method families, not a universal claim.

% -------------------------------------------------------------------
\subsection{Theorem: Bounded-Error Realizability}
\label{sec:theorem}
% -------------------------------------------------------------------

We state assumptions, theorem, and empirical scope separately.

\textbf{Mathematical assumptions} (classical, not novel):
\begin{enumerate}[nosep,label=(A\arabic*)]
\item The problem $P$ is in $\mathfrak{S}$ (Definition~\ref{def:simulability}).
\item Hadamard well-posedness: the forward map has finite Lipschitz constants $L_i$.
\item Lax--Richtmyer convergence: each primitive $p_i$ has error $\varepsilon_i \leq C_i h_i^{q_i}$.
\end{enumerate}

\begin{theorem}[Bounded-Error Realizability]
\label{thm:main}
Under (A1)--(A3), for any $\varepsilon > 0$, the three-agent pipeline produces $\hat{x}$ satisfying $\norm{\hat{x} - x^*}_X \leq \varepsilon$ in finite time.
\end{theorem}

\begin{proof}[Proof sketch]
Decompose the computation into a DAG of depth $D$ over primitives with Lipschitz constants $L_i$. Set per-node tolerance $\varepsilon_i = \varepsilon / (D \cdot L_i)$. Error propagation: $\norm{\hat{x} - x^*} \leq \sum_i L_i \varepsilon_i \leq \varepsilon$. Each $\varepsilon_i$ is achievable by mesh refinement (A3). Cost is finite for fixed resolution. Full proof in Supplementary Section~S1.
\end{proof}

\begin{remark}[What is classical vs.\ what is new]
\label{rem:classical}
The mathematical content---convergent methods converge---is the Lax equivalence theorem~\cite{lax1956}. The contribution is an automated pipeline that \emph{identifies and constructs} the convergent discretization from a natural-language input, with formal verification at each stage. The theorem provides the error contract; the agents provide the automation. The non-trivial empirical claim is that this automation works reliably (Section~\ref{sec:validation}).
\end{remark}

\textbf{Empirical scope.} We have verified primitive decomposability (condition~3) for 25 method families including FD, FEM, FVM, spectral, DG, BEM, SPH, LBM, DFT, MD, FWI, and tensor networks (Supplementary Table~S1). If a problem in $\mathfrak{S}$ exists whose discretization requires a 13th primitive, the theorem would not apply. We are not aware of such a problem but do not claim to have ruled it out.

The pipeline has four stages (Fig.~\ref{fig:pipeline}):

\textbf{Plan Agent ($\Agent_P$)} translates a natural-language problem description into a structured \texttt{spec.md} with six typed fields matching Definition~\ref{def:simulability}.

\textbf{Validation Agent ($\Agent_V$)} executes five formal mathematical checks: dimensional consistency, boundary/initial condition compatibility, Hadamard well-posedness (coercivity, CFL, Lipschitz bounds), simulability classification, and cost estimation. These are proofs, not predictions---when a check fails, the output is a mathematical diagnosis, not a confidence score.

\textbf{Computation Agent ($\Agent_C$)} selects primitives, constructs a DAG, sets resolution via a priori error estimates, executes, and verifies the error bound a posteriori.

\textbf{Quality Agent ($\Agent_Q$, new)} applies domain-specific physical checks beyond the $L^2$ error bound: monotonicity for diffusion problems, entropy conditions for shocks, conservation-law residuals, symmetry preservation, and qualitative comparison against known solution archetypes. $\Agent_Q$ does not replace the formal bound but catches the 6\% of cases (Section~\ref{sec:failure}) where the bound is met but the physics is qualitatively wrong. In our tests, $\Agent_Q$ reduces the qualitative failure rate from 6\% to 1.5\% (2/134 remaining, both involving bifurcation detection near critical parameter values).

\subsection{Prospective External Benchmark}
\label{sec:prospective}
% -------------------------------------------------------------------

To test generalization beyond the development set, we conducted a prospective benchmark with tasks the framework had never seen.

\textbf{Protocol.} We recruited 12 scientists from 9 institutions across 8 countries (Supplementary Table~S2). Each scientist submitted 6 problems from their own research, described in natural language, totaling 72 tasks. Scientists had no prior involvement in framework development and received no guidance on problem formatting. An independent coordinator (not the author) collected submissions before any were run through the pipeline, preventing cherry-picking.

\textbf{Expert baselines.} Each scientist also provided their own numerical solution as an expert baseline, computed using their standard tools (COMSOL, FEniCS, OpenFOAM, Cantera, VASP, Gaussian, or custom code). This provides a ground truth that is independent of our framework.

\subsection{Failure Analysis}
\label{sec:failure}
% -------------------------------------------------------------------

We systematically characterize failure modes using three test sets: the 12 development problems, 72 prospective tasks, and 50 targeted adversarial inputs (134 total).

\textbf{$\Agent_P$ misspecification.} $\Agent_P$ produced incorrect governing equations in 8/134 cases (6.0\%). Triggers: ambiguous variable names, missing scale information, domain jargon outside training distribution. $\Agent_V$ caught 7/8 via dimensional inconsistency or non-physical parameter ranges.

\textbf{$\Agent_V$ false negatives.} $\Agent_V$ incorrectly accepted 3/134 specifications (2.2\%) with subtle well-posedness issues (near-singular systems, condition numbers $> 10^{12}$). In 2/3 cases, $\Agent_C$ detected the issue via a posteriori checks.

\textbf{Qualitative failures.} Without $\Agent_Q$: 8/134 solutions (6.0\%) met the $L^2$ bound but exhibited qualitative artifacts (non-physical oscillations, missed symmetry-breaking, smooth solutions where shocks expected). With $\Agent_Q$: 2/134 (1.5\%), both involving bifurcation detection near critical parameter values.

\textbf{Overall.} Full pipeline with $\Agent_Q$: 122/134 correct (91.0\%), 5 correctly rejected, 5 flagged and resolved after consultation, 2 resource failures. 1 genuine wrong answer (0.7\%), 1 undetected qualitative issue near bifurcation.

\section{Discussion}
% =====================================================================

\textbf{One claim, deeply validated.}
This paper makes one claim: formal mathematical validation is the missing component that transforms AI code generation into reliable scientific simulation. The evidence is a controlled comparison (Table~\ref{tab:llm_comparison}) showing that validation reduces the silent-failure rate from 58\% to below 6\%, a prospective benchmark (Table~\ref{tab:prospective}) confirming generalization to 72 unseen tasks from 12 external scientists, and an honest failure analysis identifying the remaining 1.5\% qualitative failure rate.

\textbf{What this is not.}
This is not a claim that AI can solve all scientific problems, that 12 primitives are sufficient for all numerical methods, or that the pipeline outperforms domain-specific tools. COMSOL, FEniCS, and OpenFOAM will produce better solutions for their respective domains. The claim is narrower and more defensible: when AI generates simulation code, formal validation catches the failures that no amount of prompt engineering eliminates, and the combination is useful.

\textbf{The quality gate.}
The introduction of $\Agent_Q$ reflects a lesson from this work: formal $L^2$ error bounds are necessary but not sufficient for scientific correctness. A solution can satisfy $\norm{\hat{x} - x^*} \leq \varepsilon$ while exhibiting non-physical oscillations or missing qualitative features. $\Agent_Q$'s domain-specific checks (monotonicity, entropy, conservation, symmetry) reduced the qualitative failure rate from 6\% to 1.5\%. The remaining failures involve bifurcation detection, which requires global solution-landscape analysis---an open problem.

\textbf{Limitations.}
(1)~Primitive basis sufficiency is verified for 25 method families, not all methods.
(2)~$\Agent_P$ misspecifies 6\% of ambiguous inputs; $\Agent_V$ catches most but not all.
(3)~The prospective benchmark (72 tasks) is larger than most AI-for-science evaluations but smaller than community-scale adoption.
(4)~Real-data validation covers 3 domains deeply; extending to more is ongoing.
(5)~$\Agent_Q$ reduces but does not eliminate qualitative failures (1.5\% residual).
(6)~Single-author paper from a company developing the platform; the prospective benchmark with external scientists and independent coordinator partially mitigates this.
(7)~The pipeline requires computational resources comparable to the underlying solver; it automates setup, not execution.

\subsection{Quality Agent ($\Agent_Q$) Implementation}

$\Agent_Q$ applies a configurable set of domain-specific checks after $\Agent_C$ produces a solution:
\begin{itemize}[nosep]
\item \textbf{Conservation}: $|\sum_i m_i - M_0| / M_0 < \delta_{\text{cons}}$ for mass, energy, charge.
\item \textbf{Monotonicity}: for diffusion-dominated problems, $\partial u / \partial t \leq 0$ where expected.
\item \textbf{Entropy}: for hyperbolic systems, verify entropy inequality $\partial_t \eta + \partial_x q \leq 0$.
\item \textbf{Symmetry}: if the problem has known symmetries, check $\norm{u - \sigma(u)} / \norm{u} < \delta_{\text{sym}}$.
\item \textbf{Physical bounds}: species mass fractions $\in [0, 1]$, velocities $< c$, temperatures $> 0$.
\item \textbf{Archetype matching}: compare solution topology (number of extrema, shock locations, boundary-layer thickness) against known solution families for the problem class.
\end{itemize}
$\Agent_Q$ flags but does not reject solutions; the flag triggers expert review or automated refinement. Thresholds $\delta$ are set conservatively to minimize false positives ($< 2\%$ in our tests).

\noindent\textbf{Presubmission summary (for editors).}
Large language models can generate numerical simulation code from natural-language descriptions, but they produce silently incorrect results on the majority of non-textbook scientific problems~\cite{karniadakis2021}. We show that a formally grounded mathematical validation layer---checking well-posedness, stability, and error budgets---reduces the silent-failure rate of AI-generated solvers from 58\% to below 6\% across three deeply validated domains with real measured data (clinical CT imaging~\cite{leuschner2021}, seismic inversion~\cite{martin2006marmousi}, combustion chemistry~\cite{smith1999gri}). The validated pipeline achieves 94--99\% of domain-expert accuracy at a median 500$\times$ reduction in setup time. A prospective benchmark of 72 tasks from 12 external scientists---collected by an independent coordinator before execution---confirms generalization, with 80.6\% producing correct bounded-error solutions and only 1 wrong answer (1.4\%). This work addresses a concrete, growing problem: as AI-generated code proliferates in scientific workflows, the absence of formal correctness checks creates a new vector for silent computational error. We provide a solution grounded in classical numerical analysis, validated against real data, and tested prospectively. Code, data, benchmark, and execution logs are publicly available.
