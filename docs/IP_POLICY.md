# Intellectual Property Policy

> Clear rules so legal teams say yes.

**Version**: 1.0.0
**Status**: ACTIVE
**Rationale**: Industry and academic institutions require explicit IP clarity before contributing. Every successful open-source ecosystem (Linux, Apache, CNCF) has a clear IP framework. This is table stakes for institutional adoption.

---

## 1. License Requirements by Component

| Component | Required License | Rationale |
|-----------|-----------------|-----------|
| **PWM Core (rail)** | Apache-2.0 | Includes patent grant; protects contributors and users |
| **Solvers** | MIT or Apache-2.0 | Must be reproducible by anyone; permissive required |
| **Calibrators** | MIT or Apache-2.0 | Same as solvers |
| **Modality Packs** | MIT or Apache-2.0 | Must be usable by competing labs |
| **Primitives** | Apache-2.0 (with patent grant) | Rail components need patent protection |
| **Datasets (synthetic)** | CC-BY-4.0 | Academic reuse; citation required |
| **Datasets (real)** | Per data trust agreement | See `rails/gear05_data_trusts.md` |
| **RunBundles** | CC-BY-4.0 | Results must be citable and reusable |
| **Documentation** | CC-BY-4.0 | Open access |
| **Scoring formulas** | Apache-2.0 (as code) + CC-BY-4.0 (as spec) | Reproducibility requires open access |

**No GPL-family licenses** are accepted for contributions to the PWM registry. This ensures all PWM users can integrate components without copyleft obligations.

## 2. Contributor License Agreement (CLA)

### 2.1 When CLA Is Required

| Contribution Type | CLA Required? | Rationale |
|-------------------|---------------|-----------|
| Rail changes (harness, scoring, compiler, protocol) | **Yes** | Grants PWM Foundation right to maintain and relicense infrastructure |
| Primitives (new atomic operators) | **Yes** | Primitives become part of the rail |
| Solvers | **No** | Solver code remains fully owned by contributor |
| Calibrators | **No** | Same as solvers |
| Modality packs | **No** | Modality definitions are data, not infrastructure |
| RunBundle submissions | **No** | Results, not code |

### 2.2 CLA Terms

The CLA grants the PWM project:

1. **Non-exclusive license** to use, modify, and distribute the contributed code under Apache-2.0
2. **Right to relicense** rail code under compatible open-source licenses (not proprietary)
3. **Patent license** (for primitives): contributor grants royalty-free license to all PWM users for patents embodied in the contribution

The CLA does **not**:

1. Transfer copyright (contributor retains full ownership)
2. Restrict contributor's use of their own code
3. Apply to solver/calibrator contributions (train, not rail)

### 2.3 CLA Process

1. First-time rail contributor signs CLA via GitHub bot (one-time)
2. CLA recorded in `community/cla_signatures.json`
3. CI blocks rail PRs from contributors without signed CLA
4. CLA is the standard Apache ICLA (Individual Contributor License Agreement)

## 3. Patent Policy

### 3.1 Rail Contributions (Primitives, Harness, Scoring)

| Rule | Detail |
|------|--------|
| **Grant** | Contributing a primitive or rail component grants a royalty-free, irrevocable patent license to all PWM users |
| **Scope** | The grant covers patents necessarily infringed by using the contributed code as part of PWM |
| **Defensive termination** | If a licensee sues any PWM contributor for patent infringement related to PWM, the patent license to that licensee terminates |

### 3.2 Train Contributions (Solvers, Calibrators)

| Rule | Detail |
|------|--------|
| **No patent grant required** | Solver/calibrator contributors retain all patent rights |
| **Disclosure encouraged** | If a solver embodies a patented method, contributors are encouraged (not required) to disclose this in `meta.yaml` |
| **No enforcement on evaluation** | Contributors agree not to enforce patents against users who run their solver through the PWM harness for evaluation purposes only |

### 3.3 Standard-Essential Patents

If PWM's protocol (4-scenario, scoring formulas, LinearLikeOperator) becomes an industry standard:

- All patents contributed under CLA remain royalty-free for standard implementation
- PWM core team commits to FRAND (Fair, Reasonable, and Non-Discriminatory) terms for any standard-essential patents they hold

## 4. Data Rights

### 4.1 Synthetic Data

| Rule | Detail |
|------|--------|
| **License** | CC-BY-4.0 |
| **Generation** | Synthetic data generated by PWM tools is owned by the generator |
| **Sealed data** | CISP sealed datasets are CC-BY-4.0 but embargoed until round completion |

### 4.2 Real Data

| Rule | Detail |
|------|--------|
| **Governed by** | Data trust agreements per `rails/gear05_data_trusts.md` |
| **Minimum** | Data contributors must specify: license, allowed uses, attribution requirements, embargo period |
| **PII** | No personally identifiable information in any dataset. Medical data must be anonymized per HIPAA/GDPR. |

### 4.3 RunBundles

| Rule | Detail |
|------|--------|
| **License** | CC-BY-4.0 |
| **Includes** | Reconstructed signals, measurements, metrics, DR-IS records, provenance |
| **Does NOT include** | Solver source code (unless voluntarily submitted for reproducibility) |
| **Reuse** | Anyone can analyze, cite, and build on published RunBundles with attribution |
